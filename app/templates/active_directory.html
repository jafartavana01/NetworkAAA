Active Directory

Configures tac_plus-ng's MAVIS backend to authenticate TACACS+ users against Active Directory, instead of (or alongside) local passwords.

⚠ "Test Connection" below checks that this platform can reach and bind to AD with these settings — a real, direct LDAP connection. It does not by itself prove that tac_plus-ng's own separate MAVIS integration is working — that only takes effect once you Apply the configuration, and should be verified with a real test login afterward.
Also used to fill in the server address and search base below — override either one in Advanced if your environment needs something different.
A service account with permission to read users and groups — just the name is fine (e.g. "svc_tacacs"); the domain above is appended automatically. A full UPN (name@domain) also works if you type one directly.
Leave blank to keep the current password.
Defaults to the domain name above — override only if your domain controllers aren't directly reachable at that address.
These are two genuinely different mechanisms, not interchangeable settings for the same thing — if one fails to connect, the other is a real, separate thing to try, not just a retry. Both still depend on your domain controller having a working TLS/certificate setup at all; if neither connects, that's usually the underlying cause. "None" sends credentials unencrypted and should only be used if your directory genuinely doesn't support either.
Defaults to the domain name above, converted to dc= components.
AD group membership maps into the same group-matching policies already use — a user's AD groups (optionally filtered to this prefix) become available as User Group conditions once the config is applied. Leave this blank to report every group unfiltered — confirmed via a real, live test that this is genuinely required for any group information to be returned at all, not merely optional filtering.
